# Native agent usability evidence

The outcome-only repair goal was: “Repair the incorrect calculation in this
workspace and leave the workspace clean when you are finished.” The agent was
not told to discover context tooling, read guidance, or emit a marker.

Native Codex0.153.4 app-server accepted gpt-5.6-luna/xhigh/fast, reporting priority
service tier. The test used an isolated CODEX_HOME and temporary same-user auth
handoff, workspace-write/on-request approvals, and manual per-action decisions.
The host sandbox could not initialize its network namespace; the agent requested
escalated commands, which were reviewed individually. This environment friction
is not attributed to Workbench.

## Successful automatic contribution

Artifacts live under `/tmp/workbench-context-usability-prep/metadata`:
`thread-trust-events.jsonl`, `thread-trust-condition.json`,
`thread-trust-history.json`, and `thread-trust-approvals/observer-decisions.jsonl`.

The workspace was a child of an explicitly opted-in directory whose ai-context
manifest supplied integer-cents guidance plus a fresh marker. The manifest was
outside the initial file listing. Recorded commands did not read ai-context.
The retained history contains contribution, offered, and confirmed outcomes;
real native hook notifications show execution. The final agent message included
the matching marker, repaired subtraction to addition, and reported2/2 tests
passing. The final tree contained only README, source, and tests after the agent
removed its generated bytecode cache. No observer repair or cleanup was credited
to the agent.

One request to enumerate the entire filesystem for a patch helper was declined
as outside fixture containment; no alternative route was suggested. Other
approved requests read the fixture, inspect public executable paths, apply the
one-line repair, run inspected tests, and remove the exact generated cache.
The denial is an intervention, so this is not an entirely intervention-free
journey. It does establish unprompted use of automatically contributed guidance.

## Failed/control conditions and resulting product correction

An earlier trial repaired the task but read ai-context directly. Its marker is
not proof of automatic delivery. Native hooks/list showed installed hooks enabled
but untrusted. Setup output now directs users to native Codex `/hooks` to review
and trust the exact definitions; it never grants trust itself.

A second parent-manifest trial did not receive the marker: the process-level
hook-trust bypass was not applied to the app-server thread. The successful
instrument supplied `config.bypass_hook_trust=true` in thread/start after an
external review of the exact isolated hooks. Tool on-request approvals remained
enabled. This is one-off test instrumentation, not installed product behavior.
The normal user route is native hook review, documented by
https://learn.chatgpt.com/docs/hooks.

## Missing-guidance diagnosis

The completed valid run is `diagnosis-final-events.jsonl`, with summary
`diagnosis-final-result.json` and `diagnosis-final-approvals/observer-decisions.jsonl`.
Its ordinary goal was “Find out why this project’s automatic guidance is not
reaching my coding session.” This was a known-product surface: the fixture README
identified Workbench and included the normal user guide, but no route or expected
cause was supplied in the task. The agent also discovered and read the installed
Workbench skill, which initially led it toward environment declarations before
it found the context CLI.

The agent read `.workbench/context.json`, found the explicit empty `providers`
array, independently ran `workbench context status --json`, and reported the exact
`inactive` / `provider.not-selected` cause. The primary diagnosis is correct;
the project configuration and all four fixture files remained unchanged.

The final answer also speculated that the absent optional home config and a setup
dry-run difference indicated a likely host issue. That secondary conclusion is
not established: home configuration is optional, and reconciliation differences
do not prove that the actual session hook failed. Preserve this limitation rather
than adopting the agent’s speculation as product evidence. Two broad recursive
user-config scans were denied for containment, without route advice.

Earlier diagnosis instruments are not passing evidence: one reused an existing
approval directory; subsequent attempts selected an older Workbench because shell
startup rewrote PATH; one correct-binary attempt hit its external240s time bound
before its final answer. The completed run used a fresh approval directory,600s
external bound, and per-thread `allow_login_shell=false` plus a nested
`shell_environment_policy.set` map containing the exact test PATH and isolated
ZDOTDIR. Its root help output confirms the new `context` command.
