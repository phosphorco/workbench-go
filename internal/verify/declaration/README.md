# Repository declaration

`Evaluate(ctx, trackedBytes, verifyHome)` accepts plain Tree data. The map must
include root `workbench.pkl`; only `.pkl` entries are materialized, plus the supplied
root `PklProject.deps.json` is consumed as a lock. No checkout path is accepted.
The private materialization contains regular files, not checkout symlinks.
The module path is populated from the binary's embedded Workbench schemas.

Evaluation uses the existing pkl-go binding, backed by `pkl` on PATH. Options
express the file root, module and resource allowlists, environment, and cache
policy; no project or user settings are loaded. The server is started through
`/usr/bin/env -i PATH=... pkl`, and the Pkl environment contains PATH only. A
fresh server/evaluator is closed after every evaluation. pkl-go adds `repl:text`
for its internal evaluation expression; it supplies no ambient module data.

Only frozen `file://` modules and `modulepath:/` modules are allowed by default.
The only readable resource is exactly `prop:pkl.outputFormat`. Standard Pkl
library support is intrinsic to Pkl, as in the TypeScript evaluator.

Offline packages are an explicit extension to the reference, which rejects
all packages. `PackageCachePaths(home, uri)` identifies metadata and ZIP files
in `home/pkl/cache/package-2/<host>/<package-path>/<basename>.{json,zip}`.
Provision these through a separate dependency acquisition step; evaluation
never downloads packages. A supplied schema-version-1 `PklProject.deps.json`
must pin every remote package's metadata SHA256. Local dependency entries are
refused. Each cached metadata document must match that pin and URI, every
transitive package must also be pinned with the same checksum, and every ZIP
must match its metadata checksum. Missing or corrupt cache content refuses.
Only the exact locked package URIs are added to the module allowlist.

With no packages, CacheDir is empty (no cache). With packages, evaluation copies
only verified metadata and archives into a fresh private package cache under
VERIFY_HOME and deletes it afterward. This is the necessary package-content
exception to the reference's `--no-cache`: Pkl cannot resolve offline packages
without a package cache while preserving the resource allowlist. There is no
persistent evaluator/output cache, and no network resource is allowed, even for
package resolution. A custom package reader was rejected because pkl-go's
reader protocol does not express Pkl's fragment-relative package resolution.
Native package resolution preserves relative imports and dependency semantics.

`Declaration.Repository` uses the shared Pkl policy types. `Manifests` retains
the evaluated JSON field order: converting `requires` to a Go map and encoding
it would sort its keys and change versions. `Register` therefore accepts raw
manifest JSON, decodes it to the shared `Verifier`, and hashes bytes matching
`JSON.stringify`. `Order` visits sorted verifier IDs and sorted upstream IDs,
returning registered verifiers in dependency order or a cycle path.

Goldens were generated by running the TypeScript `Manifest.order/register`
against the reference demo. To regenerate, run:

```
bun run internal/verify/declaration/testdata/generate.mts /path/to/tools/verify
```

The generator copies the demo's four Pkl documents, records all three verifier
versions, and adds a registration fixture with non-sorted requires keys,
HTML characters, Unicode line separators, literal escapes, and a small number.
